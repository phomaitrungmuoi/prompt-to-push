01Install · 1 of 3

Install Git

Git is the engine underneath everything else. Install it once, tell it who you are, and you are done.

  1. 1

    Install it with your system's package manager

    • Command Line Toolsxcode-select --install
    • or Homebrewbrew install git
    • PowerShellwinget install --id Git.Git -e --source winget

    Prefer a classic installer? Download it from git-scm.com and keep the default options. They include Git Bash.

    • Debian / Ubuntusudo apt update && sudo apt install git
    • Fedorasudo dnf install git
    • Archsudo pacman -S git
  2. 2

    Check that it works

    terminal
    $ git --version
git version 2.56.1
  3. 3

    Introduce yourself

    Git stamps every commit with a name and an email. Use the email of your GitHub account so your commits link to your profile.

    terminal
    $ git config --global user.name "Your Name"
$ git config --global user.email "you@example.com"
$ git config --global init.defaultBranch main

On Windows? Install Git first.

Claude Code on Windows runs its commands through Git Bash, which comes with Git for Windows.

01Install · 2 of 3

Get GitHub ready

GitHub keeps your repository in the cloud and can host it as a website. The GitHub CLI, gh, lets you (and Claude) drive it from the terminal.

  1. 1

    Create a free account

    Sign up at github.com/signup and verify your email. Then turn on two-factor authentication in Settings → Password and authentication.

  2. 2

    Install the GitHub CLI

    • Homebrewbrew install gh
    • PowerShellwinget install --id GitHub.cli
    • Debian / Ubuntusudo apt install gh
    • Fedorasudo dnf install gh
    • Archsudo pacman -S github-cli

    Want the newest release on Debian or Ubuntu? Add the official package repository from cli.github.com.

  3. 3

    Check it

    terminal
    $ gh --version
gh version 2.104.0 (2026-11-12)

Your username matters

Your free website address is built from it:

https://username.github.io/repo/

Why use the CLI?

  • Signs Git in with a secure token, no passwords typed into prompts.
  • Creates repositories without opening a browser.
  • Turns on GitHub Pages with a single command.
  • Claude can run the very same commands for you.

Install Claude Code

Claude Code is Anthropic's coding agent for the terminal. It reads your project, edits files and runs commands, always within the permissions you set.

  1. 1

    Run the installer

    • Native installercurl -fsSL https://claude.ai/install.sh | bash
    • or Homebrewbrew install --cask claude-code
    • PowerShellirm https://claude.ai/install.ps1 | iex

    Needs Git for Windows (for Git Bash). Using WSL instead? Run the Linux command inside it.

    • Native installercurl -fsSL https://claude.ai/install.sh | bash

    Works on Ubuntu, Debian, Fedora, Arch and WSL. The native install updates itself in the background.

  2. 2

    Verify the install

    terminal
    $ claude --version
2.1.328 (Claude Code)
$ claude doctor   # checks your install
  3. 3

    Open a project and sign in

    terminal
    $ cd my-site
$ claude

    The first launch opens your browser to sign in. Inside Claude Code, type /login to switch accounts and /help to list every command.

Link your terminal to GitHub

Pushing needs proof that it is really you. The GitHub CLI signs you in once, stores a secure token, and hands it to Git, so git push just works, for you and for Claude.

sign in once
$ gh auth login
? Where do you use GitHub? GitHub.com
? Preferred protocol for Git operations? HTTPS
? Authenticate Git with your GitHub credentials? Yes
? How would you like to authenticate? Login with a web browser
! First copy your one-time code: 1A2B-3C4D
✓ Authentication complete.
✓ Logged in as your-username
confirm
$ gh auth setup-git   # only needed if you answered "No" above
$ gh auth status
✓ Logged in to github.com account your-username
  - Git operations protocol: https
create & register a key
$ ssh-keygen -t ed25519 -C "you@example.com"
$ gh ssh-key add ~/.ssh/id_ed25519.pub --title "My laptop"
$ ssh -T git@github.com
Hi your-username! You've successfully authenticated, but GitHub does not provide shell access.

With SSH, use remote URLs that look like git@github.com:your-username/my-site.git. If gh ssh-key add asks for more access, run gh auth refresh -s admin:public_key first.

What happens on every push

git pushYou or Claude, in the terminal
Credential helpergh supplies the token from your keyring
github.comChecks the token and accepts the commits

Claude never sees your password. It runs git push, and Git asks gh for the token.

02Connect · 2 of 2

Create a repo and go live

A handful of commands take you from an empty folder to a public website. This folder becomes the codebase Claude works in.

  1. 1

    Create the project folder

    terminal
    $ mkdir my-site && cd my-site
$ git init -b main
$ echo "<h1>Hello, world</h1>" > index.html
  2. 2

    Make the first commit

    terminal
    $ git add index.html
$ git commit -m "chore: first commit"
  3. 3

    Create the GitHub repo and push, in one go

    terminal
    $ gh repo create my-site --public --source=. --remote=origin --push
✓ Created repository your-username/my-site on GitHub
✓ Added remote https://github.com/your-username/my-site.git
✓ Pushed commits to https://github.com/your-username/my-site.git
  4. 4

    Turn on GitHub Pages

    terminal
    $ gh api -X POST "repos/{owner}/{repo}/pages" \
    -f "source[branch]=main" -f "source[path]=/"

    Prefer clicking? Open the repo → Settings → Pages → Deploy from a branch → main / (root).

your-username.github.io/my-site/
Hello, world

Live in about a minute

Every push to main redeploys the site automatically. Check progress with gh run list, open the repo with gh browse.

03Permissions · 1 of 2

Let Claude commit & push on its own

Out of the box, Claude Code asks before running commands such as git commit. Allow and deny rules decide what it may do without asking, and what it may never do.

A

Approve once, remember

When Claude asks to run a command, choose “Yes, and don't ask again” to save a rule for it.

Bash command
git commit -m "feat: add footer"
Do you want to proceed?
1. Yes
❯ 2. Yes, and don't ask again for git commit commands
3. No, and tell Claude what to do differently
B

The /permissions menu

Type /permissions inside Claude Code to see every rule, and add or remove them in an interactive menu.

> /permissions
AllowAskDeny
✓ Bash(git commit:*)
✓ Bash(git push:*)
+ Add a new rule…
C

A settings file

Write the rules once in .claude/settings.json. Commit it, and everyone on the project gets the same setup.

  • ~/.claude/settings.jsonYou, in every project
  • .claude/settings.jsonThis project, shared with the team
  • .claude/settings.local.jsonThis project, only you (git-ignored)
.claude/settings.json
{
  "permissions": {
    "allow": [
      "Bash(git status)",
      "Bash(git diff:*)",
      "Bash(git log:*)",
      "Bash(git add:*)",
      "Bash(git commit:*)",
      "Bash(git push:*)",
      "Bash(git pull:*)"
    ],
    "deny": [
      "Bash(git push --force:*)",
      "Bash(git push -f:*)",
      "Bash(git reset --hard:*)",
      "Read(./.env)"
    ]
  }
}
  1. 1
    Look freely. Read-only commands like status, diff and log never change anything, so they run without a prompt.
  2. 2
    Ship without asking. add, commit, push and pull are pre-approved. :* means “this command with any arguments”.
  3. 3
    Block the dangerous ones. Force-push and hard reset are refused. A deny rule always wins over an allow rule.
  4. 4
    Keep secrets unread. Claude cannot open your .env file, so its values never reach a prompt or a commit.

Belt and braces

Also add a branch protection rule for main on GitHub (Settings → Branches). It blocks force-pushes on the server, whatever any tool tries.

03Permissions · 2 of 2

Tell Claude when to ship

Permissions decide what Claude may run. A CLAUDE.md file in your project says when and how, and Claude reads it at the start of every session.

CLAUDE.md
# Project rules

## Git workflow
- When a task is finished and checks pass, commit and push without asking.
- Stage only the files you changed (`git add <files>`), never `git add -A`.
- Use Conventional Commit messages: feat:, fix:, docs:, style:, refactor:.
- Push to `origin main`, or to the current branch.
- Never force-push or rewrite history that is already on GitHub.
- Never commit secrets: .env files, keys or tokens.

Starting from scratch? Run /init inside Claude Code to generate a CLAUDE.md from your project, then paste in the Git section.

try it
> Add a contact section to the homepage, then ship it.
Update(index.html)+24
Bash(git commit -m "feat: add contact section")
⎿ ran without a prompt: allowed by settings
Bash(git push origin main)
⎿ main → origin/main

Permission modes

Press Shift + Tab inside Claude Code to cycle through them.

  • DefaultAsks before edits and before any command not on your allow list.
  • Accept editsEdits files without asking. Commands still follow your rules.
  • PlanRead-only. Researches and proposes a plan before changing anything.
claude --permission-mode acceptEdits

Safety checklist

  • Deny force-push and git reset --hard
  • Protect main with a branch rule on GitHub
  • Keep secrets in .env and list it in .gitignore
  • Undo any commit with git revert <sha>
  • Skip --dangerously-skip-permissions on your own machine
